# Model-page Stage B review — Lattice QM and Lattice Fields

## Scope and page hierarchy

Stage B standardizes the two existing Gaussian model pages without changing their numerical models. Each left sidebar begins with the action, measure and units, followed immediately by collapsible geometry, physical-parameter and sampler drafts. The main column presents Run/Pause, Step, Reset and key readings; one full-width featured display; **Measurements & diagnostics** with zero to six optional cards; collapsible technical details and measurement coverage; and a short collapsible **Mathematics, exercises & suggested experiments** section. QM explains Euclidean versus algorithmic and real time, finite-spacing/continuum gaps, correlators, transfer quadrature and reflection-positivity limits. Fields explains the precision/covariance relation, ordinary versus mean-zero measures, boundaries, zero-mode removal, correlated sampling and finite-volume Fourier references. Both link to the existing mathematical notes. Optional transfer, reflection and Fourier analyses remain selectable tools, rather than permanent panels.

**Add tool** now creates a card directly. The pure `nextGalleryTool` helper chooses the first currently suitable tool absent from both stage and gallery, in each model's established order. A nonperiodic field does not default to a Fourier spectrum, although its card selector still permits that view and explains its limitation. Once suitable types are represented, Add chooses a useful duplicate. The gallery cannot exceed six cards, regardless of the featured assignment, and a new card becomes the active phone detail. A card's selector can change its renderer immediately. The featured selector **replaces** a tool in its current keyed placement; a gallery card's **Feature** action **exchanges** whole placements. Neither operation silently evicts another card. A single open gallery card occupies the full desktop row; two or more open cards occupy two columns. Explicit expansion still spans both columns, while collapsed cards do not narrow the sole open view. Chart SVGs have an internal maximum width so a full-row card does not distort axes.

Card actions are compact text controls, with accessible names, visible focus, disabled states and touch-size targets. The scientific renderer's own title and axis labels remain, while redundant visible card headings are suppressed except in phone overview. The Run/Pause control remains the primary visual action; Apply parameters is distinguished from display controls. The oscillator action is aligned onto two mathematical lines, fitting the ordinary desktop sidebar without cropping. The phone layout retains a visible featured stage, single-detail gallery and compact overview. The formula remains readable at 360 px with local KaTeX/MathML assets.

Path range and effective-gap lag appear with their respective QM tools. Field profile/history ranges, shared selected site and inspection comparison site appear only beside relevant tools; Fourier momentum remains in the spectrum tool. Choices that should persist across React remounts are stored by assignment key in the owning workspace, including field range/partner/momentum and QM path range/lag. The selected field site is intentionally shared across related views. Removing an assignment releases its keyed choices. Physical parameters and sampler settings remain in the sidebar. All these controls read already delivered snapshots and cannot advance the worker.

## Scientific and architecture boundaries

This stage changes only React presentation, CSS, text and tests. Field and oscillator actions, references, Gaussian/Fourier samplers, RNG consumption, warm-up and measurement schedules, segment boundaries, worker protocols and archive formats are unchanged. The two workspaces retain independent mounted numerical sessions. Hidden or collapsed optional analyses do not run; transfer quadrature remains lazy and cached. Tool selection does not create a second active copy of expensive analysis. The presentation layer continues to use model-specific renderers and a small pure assignment module; there is no general plugin framework or new dependency. The branch keeps `src/models`, `src/algorithms` and worker code untouched.

The later Small Systems migration should relabel its display-only **Fit All** action **Refit axes** and move its global Histogram overlay checkbox into each applicable distribution-card assignment. Stage B does not alter those controls. Small Systems, Lattice Systems and Experiments have not yet undergone the full model-page migration; no named-example catalog, custom graph editor, interacting field or new physics is included.
