# Stage E — Custom simple Ising graph review

## Scientific and interface contract

**Custom Ising graph (2–4 spins)** is directly selectable in Advanced Small Systems examples. It is a recipe over the existing `ising` family, not a new sampler or mathematical model. The default is four sites joined as an open three-bond chain at K=0.5, b=0. The applied domain has ID `custom-simple-ising`, vertices `v0` through `v(n−1)`, and one undirected pair record per explicitly present `i<j`, with canonical ID `pair:v<i>:v<j>` and stored orientation from the lower to higher index. Edges occur in deterministic pair order. No custom face, self-link, parallel bond or periodic metadata is inferred. The named torus remains a separate cell complex with eight bonds and four oriented faces.

The dimensionless action remains `S(s)=−Σ_present K_e s_tail(e)s_head(e)−Σ_i b_i s_i`, with `s_i=±1` and K,b∈[−10,10]. A present edge with K=0 still has an ID, SVG bond and local-inspection entry. An absent pair has neither an edge record nor a coupling in the applied model or portable capture. The two choices can have identical Gibbs probabilities but different scientific topology and `topologyKey`. The custom validator enforces these restrictions only for `custom-simple-ising`; generic domains still admit multigraphs and self-links.

The sidebar owns an unsubmitted draft of n, presence, K and b. Changing a checkbox or typing a value leaves the featured graph and worker untouched. A temporarily unchecked pair retains its typed K until Apply; once an absent pair has been applied and the editor remounts, re-enabling starts at the disclosed K=0.5 default. Apply with a changed site count or edge-presence set starts a seeded session, clearing incompatible history and resetting site/bond selection. K or b changes on the same topology preserve the current configuration and RNG while beginning an isolated measurement segment, including a present K crossing zero. Reset uses applied settings. The chooser continues to show the custom example as **modified** after edits; its catalog ID and disabled draft values do not enter worker settings or archives.

The featured SVG draws only applied edges at reviewed two-site horizontal, three-site triangular and four-site square coordinates. Short endpoint labels keep custom bonds readable; accessible names and the bond selector retain full canonical IDs. Geometric proximity alone never creates a physical interaction. The existing exact finite-state panel, local conditional inspection, spin configuration, distribution, trajectory, convergence, acceptance and correlation tools are reused without altered sampling decisions or RNG consumption.

## Validation and compatibility

`src/models/customIsing.test.ts` independently enumerates all **74** labeled presence patterns: 2 for n=2, 8 for n=3 and 64 for n=4. For every pattern it checks canonical IDs/incidence, no self/parallel/face records, full action against a separate finite sum, normalized exact masses, log Z, local flip costs, conditional probabilities and both local detailed-balance laws. Hand-checkable limits include `Z=2^n` for the empty zero-field graph; present K=0 versus absent; agreement with named dimer and triangle exact results; six lowest-action states for the equal-antiferromagnetic triangle; disconnected-component factorization; and strong finite fields. Direct, local heat-bath and lazy Metropolis transitions have seeded replay checks. The existing torus edge/face tests remain unchanged.

`SimulationRun` checks confirm same-topology parameter segments retain state and RNG, while topology changes are rejected by `changeSettings` and begin a fresh run through the existing initialization route. Current and historical custom captures keep their own active domains and measurements. Version-1 JSON bundle export/import and CSV output reuse established formats; a tampered phantom inactive coupling is rejected. Existing version-2 import, archive bounds and provenance suites are part of the full check. Browser tests verify all six pair controls, draft isolation, site-count changes, edge removal and stable IDs, negative and zero K, empty/disconnected graphs, exact/local tools, named-preset and torus compatibility, current-segment archive round trip, direct/heat-bath/Metropolis controls, Run/Pause and identical seeded scientific captures with and without display-only interactions. Tests run on desktop Chromium, a 360 px phone viewport and mobile WebKit.

The complete `npm run check` pipeline passed: Prettier, TypeScript, **370 unit tests in 48 files**, production `/lattice/` build, and **274 passing browser tests** across the three projects (two existing sweep-budget skips). `git diff --check` passed. The 360 px editor presents one compact numeric row per available pair and has no horizontal overflow.

Source readability follows the repository standard: `customSimpleIsingDomain` is a small pure topology constructor, `customIsingModel` materializes only active scientific parameters, `CustomIsingGraphEditor` owns draft UI state, and `SmallSystemsApp` retains the sole Apply/session routing decision. Numerical modules remain testable without React. No dependency, worker protocol, archive schema, generic drag-and-drop graph editor, gauge variable or new Ising kernel was added. General graph drawing/editing, explicit face construction, gauge lessons and larger graph sizes remain deferred. The existing Vite main-chunk advisory and absence of a low-end physical-phone performance measurement remain limitations.
