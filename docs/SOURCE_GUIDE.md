# Reading the Lattice Lab source

Start with the numerical path before the React components: **domain → model → sampler → run/measurement recorder → worker/client → plot or workspace**. The functions below are hand-authored entry points. `docs/SPECIFICATION.md` defines the mathematical contract; milestone reviews explain why the implementation has its present limits.

| Feature to trace | Read in this order |
| --- | --- |
| A simple Gaussian | `src/models/gaussian.ts` (`gaussianAction`, `gaussianReference`) → `src/algorithms/gaussianSampler.ts` (`sampleGaussian`) → `src/engine/simulationEngine.ts` (`SimulationRun.advance`) → `src/models/gaussian.test.ts` and `src/algorithms/sampling.test.ts`. The dimensionless action is `S(x)=a x²/2−hx`, and a direct draw uses two RNG uniforms. |
| A massive Gaussian lattice field (M4a1) | Start with the two-site calculation in [`math/gaussian-fields.md`](math/gaussian-fields.md), then read `src/domain/fieldLattice.ts` (`createFieldLattice`) → `src/models/gaussianField.ts` (`fieldAction`, `fieldPrecision`, `fieldConditional`) → `src/models/gaussianFieldReference.ts` (`exactGaussianField`) → `src/algorithms/gaussianFieldSampler.ts` (`fieldTransition`) → `src/engine/fieldRun.ts` (`FieldRun.advance`) → `src/app/FieldWorkspace.tsx`. The tiny-matrix, sampler and segment oracles are in the corresponding `.test.ts` files; `tests/browser/fields.spec.ts` checks display-only choices. |
| A periodic Fourier field and mean-zero GFF (M4a2) | Read [`math/gaussian-fourier.md`](math/gaussian-fourier.md), then `src/domain/fieldLattice.ts` → `src/models/fieldFourier.ts` (`createFourierBasis`, `forwardRealFourier`, `inverseFourier`) → `src/models/gaussianFieldSpectral.ts` (`spectralGaussianField`) → `src/algorithms/spectralFieldSampler.ts` (`drawSpectralField`) → `src/observables/fieldSpectrum.ts` (`sampledModePower`) → `src/engine/fieldRun.ts` (`newSegment`, `advance`) → `src/app/FieldSpectrum.tsx` and `FieldWorkspace.tsx`. The corresponding `.test.ts` files contain independent DFT, augmented-matrix and seeded checks. |
| A Euclidean harmonic oscillator (M4b) | Read [`math/euclidean-oscillator.md`](math/euclidean-oscillator.md), then `src/models/oscillator.ts` (`oscillatorAction`, `oscillatorField`) → `src/models/oscillatorReference.ts` (`fourierCorrelator`, `latticeCorrelator`, `oscillatorPartition`) → `src/observables/oscillatorCorrelator.ts` (`segmentCorrelator`, `effectiveGap`) → `src/models/oscillatorTransfer.ts` (`transferKernel`, `transferQuadrature`, `reflectionExample`) → the reused `src/algorithms/gaussianFieldSampler.ts`, `spectralFieldSampler.ts` and `src/engine/fieldRun.ts` → `src/app/OscillatorControls.tsx`, `OscillatorTheory.tsx` and `OscillatorView.tsx`. Start with `oscillator.test.ts`'s four-site precision and action, then `oscillatorTransfer.test.ts`, `oscillatorRun.test.ts`, and `tests/browser/oscillator.spec.ts`. The pure mathematical modules can be read and tested without React. |
| Finite graph Ising and enumeration | `src/domain/graph.ts` (`graphPreset`, `validateDomain`) → `src/models/ising.ts` (`isingAction`, `flipDifference`, `conditionalPlus`, `exactIsing`) → `src/models/ising.test.ts`. Each edge ID contributes separately, even for periodic parallel bonds. |
| A local Monte Carlo update | `src/algorithms/transitions.ts` (`transition`) for one-variable models, `src/algorithms/isingTransition.ts` (`isingTransition`) for graph Ising, or `src/algorithms/latticeTransition.ts` (`latticeTransition`) for 2D Ising. Compare with `src/algorithms/transitions.test.ts` and `src/algorithms/latticeTransition.test.ts`. These are algorithmic updates, not physical time. |
| A lattice simulation worker | `src/domain/indexedLattice.ts` (`createIndexedLattice`) → `src/models/latticeIsing.ts` (`totalEnergy`, `flipEnergy`) → `src/engine/latticeRun.ts` (`LatticeRun.advance`, `LatticeEngine.handle`) → `src/workers/lattice.worker.ts` → `src/engine/latticeClient.ts` (`LatticeClient.receive`). `src/engine/latticeRun.test.ts` checks update and segment behavior. |
| A measured observable | `src/observables/moments.ts` (`recordMoment`, `summarizeMoments`) and `src/observables/latticePhysics.ts` (`bondProducts`, `axialProducts`, `equilibriumFluctuations`) → the measurement branch of `LatticeRun.advance` → `src/observables/latticePhysics.test.ts`. Full-segment aggregates and bounded plot histories have different coverage. |
| Autocorrelation and uncertainty | `src/observables/statisticalDiagnostics.ts` (`analyzeSeries`, `DiagnosticHistory`) → `src/models/isingMarkov.ts` (`exactMarkovDiagnostics`) → `src/app/StatisticalDiagnostics.tsx` and `src/plotting/DiagnosticPlots.tsx`. Read `src/observables/statisticalDiagnostics.test.ts` and `src/models/isingMarkov.test.ts` to distinguish empirical recent-window estimates from exact stationary results. |
| An archived experiment | `src/engine/protocol.ts` (`SmallCapture`) or `src/engine/latticeRun.ts` (`LatticeCapture`) → `src/experiments/archive.ts` (`createArchiveEntry`, `validateScientific`, `importBundle`) → `src/experiments/export.ts` (`exportSummaryCsv`, `exportMeasurementsCsv`) → `src/app/Experiments.tsx`. See `src/experiments/archive.test.ts` and `src/experiments/export.test.ts` for provenance and portable-data checks. |
| A parameter sweep | `src/experiments/sweepPlan.ts` (`pointConfiguration`, `validateSweepPlan`) → `src/experiments/sweepRun.ts` (`SweepRun.advance`) → `src/workers/sweep.worker.ts` → `src/experiments/sweepClient.ts` → `src/app/SweepWorkspace.tsx` (`archivePoint`, `finalize`) → `src/experiments/sweepArchive.ts`. `src/workers/sweep.worker.test.ts` drives the real command handler; `src/experiments/sweep.test.ts` independently replays point runs. |
| Rendering and browser interaction | `src/app/App.tsx` keeps the four workspaces mounted; `src/app/useSimulation.ts`, `src/app/LatticeSystems.tsx` and `src/app/FieldWorkspace.tsx` connect React to worker clients. `src/plotting/viewport.ts` and `src/plotting/LatticePlots.tsx` project snapshots into views; `src/app/styles.css` holds responsive rules. `tests/browser/` exercises the production build at desktop and phone sizes. |

Run `npm test` for the unit tests beside the numerical modules. Run `npm run build` and then `npm run test:browser` for production-browser tests; `npm run check` also runs formatting and typecheck. For independent references, start with the Gaussian analytic moments in `gaussian.test.ts`, the hand-enumerated tiny Ising cases in `ising.test.ts`, the 2×2 physical reference comparisons in `latticeExact.test.ts`, and the separate `LatticeRun` point replay in `sweep.test.ts`. The tests should make the expected result intelligible without trusting the production function under test.
