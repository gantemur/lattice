# Reading the Lattice Lab source

Start with the numerical path before the React components: **domain → model → sampler → run/measurement recorder → worker/client → plot or workspace**. The functions below are hand-authored entry points. `docs/SPECIFICATION.md` defines the mathematical contract; milestone reviews explain why the implementation has its present limits.

| Feature to trace | Read in this order |
| --- | --- |
| Quartic-path HMC (M4c2) | First derive the force from [`math/hmc-euclidean-qm.md`](math/hmc-euclidean-qm.md) and hand-check `quarticPathGradient` in `src/models/quarticOscillator.ts`. Read `src/algorithms/quarticHmc.ts` in the order auxiliary Hamiltonian → deterministic leapfrog → refreshed-momentum corrected transition; `quarticHmc.test.ts` independently checks full-action differences, reversibility, an 8×8 Jacobian, second-order energy defect and the `2N+1` uniform budget. Then follow `src/engine/fieldRun.ts` for the discriminated cadence, segment isolation, measurements and bounded diagnostics; `fieldClient.ts` for 16-trajectory scheduling; and `src/app/QuarticOscillatorControls.tsx`, `QuarticHmcDiagnostics.tsx` and `QuarticOscillatorView.tsx` for draft, display and inspection state. `quarticHmcRun.test.ts`, `quarticHmcBenchmark.test.ts`, `fieldHmcClient.test.ts` and `tests/browser/quarticHmc.spec.ts` close the worker, equilibrium and presentation loop. The model force and HMC kernel have no React dependency. |
| A simple Gaussian | `src/models/gaussian.ts` (`gaussianAction`, `gaussianReference`) → `src/algorithms/gaussianSampler.ts` (`sampleGaussian`) → `src/engine/simulationEngine.ts` (`SimulationRun.advance`) → `src/models/gaussian.test.ts` and `src/algorithms/sampling.test.ts`. The dimensionless action is `S(x)=a x²/2−hx`, and a direct draw uses two RNG uniforms. |
| A massive Gaussian lattice field (M4a1) | Start with the two-site calculation in [`math/gaussian-fields.md`](math/gaussian-fields.md), then read `src/domain/fieldLattice.ts` (`createFieldLattice`) → `src/models/gaussianField.ts` (`fieldAction`, `fieldPrecision`, `fieldConditional`) → `src/models/gaussianFieldReference.ts` (`exactGaussianField`) → `src/algorithms/gaussianFieldSampler.ts` (`fieldTransition`) → `src/engine/fieldRun.ts` (`FieldRun.advance`) → `src/app/FieldWorkspace.tsx`. The tiny-matrix, sampler and segment oracles are in the corresponding `.test.ts` files; `tests/browser/fields.spec.ts` checks display-only choices. |
| A periodic Fourier field and mean-zero GFF (M4a2) | Read [`math/gaussian-fourier.md`](math/gaussian-fourier.md), then `src/domain/fieldLattice.ts` → `src/models/fieldFourier.ts` (`createFourierBasis`, `forwardRealFourier`, `inverseFourier`) → `src/models/gaussianFieldSpectral.ts` (`spectralGaussianField`) → `src/algorithms/spectralFieldSampler.ts` (`drawSpectralField`) → `src/observables/fieldSpectrum.ts` (`sampledModePower`) → `src/engine/fieldRun.ts` (`newSegment`, `advance`) → `src/app/FieldSpectrum.tsx` and `FieldWorkspace.tsx`. The corresponding `.test.ts` files contain independent DFT, augmented-matrix and seeded checks. |
| A Euclidean harmonic oscillator (M4b) | Read [`math/euclidean-oscillator.md`](math/euclidean-oscillator.md), then `src/models/oscillator.ts` (`oscillatorAction`, `oscillatorField`) → `src/models/oscillatorReference.ts` (`fourierCorrelator`, `latticeCorrelator`, `oscillatorPartition`) → `src/observables/oscillatorCorrelator.ts` (`segmentCorrelator`, `effectiveGap`) → `src/models/oscillatorTransfer.ts` (`transferKernel`, `transferQuadrature`, `reflectionExample`) → the reused `src/algorithms/gaussianFieldSampler.ts`, `spectralFieldSampler.ts` and `src/engine/fieldRun.ts` → `src/app/OscillatorControls.tsx`, `OscillatorTheory.tsx` and `OscillatorView.tsx`. Start with `oscillator.test.ts`'s four-site precision and action, then `oscillatorTransfer.test.ts`, `oscillatorRun.test.ts`, and `tests/browser/oscillator.spec.ts`. The pure mathematical modules can be read and tested without React. |
| An interacting Euclidean oscillator (M4c1) | Start with [`math/interacting-oscillator.md`](math/interacting-oscillator.md) and the direct four-site formula in `src/models/quarticOscillator.test.ts`. Read `src/models/quarticOscillator.ts` (`quarticPathAction`, `quarticLocalDifference`, `potentialMinimum`) → `src/algorithms/quarticOscillatorSampler.ts` (`quarticTransition`) → `src/engine/fieldRun.ts` (explicit model dispatch, nullable interacting reference, segment aggregates) → `src/observables/quarticCorrelator.ts` → `src/models/quarticTransfer.ts` (positive Nyström matrix, full eigenpairs, three-grid study) → `src/workers/quarticTransfer.worker.ts` and `src/app/useQuarticTransfer.ts` (lazy independent analysis) → `src/app/QuarticOscillatorControls.tsx`, `QuarticPlots.tsx` and `QuarticOscillatorView.tsx`. Read `quarticRun.test.ts` for seeded/segment invariants, `quarticTransfer.test.ts` for independent trace/finite-difference checks, then `tests/browser/quarticOscillator.spec.ts`. The action, sampler and transfer mathematics are testable without React. |
| Named examples and small Ising graphs (D3) | `src/app/smallCatalog.ts` maps a stable presentation-only example ID to an existing model plus sampler; `src/domain/graph.ts` (`isingGraphPreset`) builds dimer, chain and triangle topology with no inferred faces; `src/models/ising.ts` provides the unchanged action and exact sampler; `SmallSystemsApp.tsx` chooses the existing segment or seeded-session path; `ScalarSettings.tsx` follows applied sampler changes. Read `src/app/smallCatalog.test.ts` for closed-form, local-balance and replay checks, then `tests/browser/pedagogicalCatalogD3.spec.ts` for phone, selection and segment behavior. |
| Custom simple Ising graph (Stage E) | `src/domain/graph.ts` (`customPairIds`, `customSimpleIsingDomain`, `validateCustomSimpleIsingDomain`) defines stable pair presence without changing generic multigraph validation → `src/models/ising.ts` (`customIsingModel`, `validateIsing`) materializes only active K and b → the unchanged `exactIsing`/`isingTransition`/`SimulationRun` supply science → `src/app/CustomIsingGraphEditor.tsx` owns unsubmitted draft choices and `SmallSystemsApp.tsx` routes Apply by `topologyKey` → `GraphVisualization` draws only applied edges. Read `src/models/customIsing.test.ts` for all 74 labeled presence patterns, finite sums, balance, segment and archive checks, then `tests/browser/customIsingStageE.spec.ts` for draft isolation, selectors, seeded capture replay and phone layout. |
| Finite graph Ising and enumeration | `src/domain/graph.ts` (`graphPreset`, `validateDomain`) → `src/models/ising.ts` (`isingAction`, `flipDifference`, `conditionalPlus`, `exactIsing`) → `src/models/ising.test.ts`. Each edge ID contributes separately, even for periodic parallel bonds. |
| A 1D Ising transfer calculation | Start with [the mathematical guide](math/ising-chain-transfer.md), then `src/models/isingChainTransfer.ts` (`transferMatrix`, `transferSpectrum`, `finiteChainReference`) for scaled 2×2 products, open boundary vectors, finite correlations and bulk ξ. `src/models/isingChainTransfer.test.ts` independently enumerates short spin words and checks the closed zero-field formulas and existing four-spin graph ring. Next read `src/domain/indexedLattice.ts` for the no-y-bond chain and `src/engine/latticeRun.ts` for full-segment spatial measurements. `src/app/ChainSystems.tsx` owns only the applied/draft session boundary; `SpinChain.tsx` and `ChainToolDeck.tsx` render read-only views. `src/engine/isingChainRun.test.ts` checks RNG, segments and archives; `tests/browser/isingChain.spec.ts` covers the page and phone. |
| A local Monte Carlo update | `src/algorithms/transitions.ts` (`transition`) for one-variable models, `src/algorithms/isingTransition.ts` (`isingTransition`) for graph Ising, or `src/algorithms/latticeTransition.ts` (`latticeTransition`) for indexed 1D/2D physical Ising. Compare with `src/algorithms/transitions.test.ts` and `src/algorithms/latticeTransition.test.ts`. These are algorithmic updates, not physical time. |
| A lattice simulation worker | `src/domain/indexedLattice.ts` (`createIndexedLattice`) → `src/models/latticeIsing.ts` (`totalEnergy`, `flipEnergy`) → `src/engine/latticeRun.ts` (`LatticeRun.advance`, `LatticeEngine.handle`) → `src/workers/lattice.worker.ts` → `src/engine/latticeClient.ts` (`LatticeClient.receive`). `src/engine/latticeRun.test.ts` checks update and segment behavior. |
| A measured observable | `src/observables/moments.ts` (`recordMoment`, `summarizeMoments`) and `src/observables/latticePhysics.ts` (`bondProducts`, `axialProducts`, `equilibriumFluctuations`) → the measurement branch of `LatticeRun.advance` → `src/observables/latticePhysics.test.ts`. Full-segment aggregates and bounded plot histories have different coverage. |
| Autocorrelation and uncertainty | `src/observables/statisticalDiagnostics.ts` (`analyzeSeries`, `DiagnosticHistory`) → `src/models/isingMarkov.ts` (`exactMarkovDiagnostics`) → `src/app/StatisticalDiagnostics.tsx` and `src/plotting/DiagnosticPlots.tsx`. Read `src/observables/statisticalDiagnostics.test.ts` and `src/models/isingMarkov.test.ts` to distinguish empirical recent-window estimates from exact stationary results. |
| An archived experiment | `src/engine/protocol.ts` (`SmallCapture`) or `src/engine/latticeRun.ts` (`LatticeCapture`) → `src/experiments/archive.ts` (`createArchiveEntry`, `validateScientific`, `importBundle`) → `src/experiments/export.ts` (`exportSummaryCsv`, `exportMeasurementsCsv`) → `src/app/Experiments.tsx`. See `src/experiments/archive.test.ts` and `src/experiments/export.test.ts` for provenance and portable-data checks. |
| A parameter sweep | `src/experiments/sweepPlan.ts` (`pointConfiguration`, `validateSweepPlan`) → `src/experiments/sweepRun.ts` (`SweepRun.advance`) → `src/workers/sweep.worker.ts` → `src/experiments/sweepClient.ts` → `src/app/SweepWorkspace.tsx` (`archivePoint`, `finalize`) → `src/experiments/sweepArchive.ts`. `src/workers/sweep.worker.test.ts` drives the real command handler; `src/experiments/sweep.test.ts` independently replays point runs. |
| Rendering and browser interaction (M4c0 and model-page Stages A–D2) | `src/app/App.tsx` keeps five workspaces mounted and routes them with `workspaceForHash`; `SiteHeader.tsx` gives them one navigation order. `useField.ts` creates independent QM and Fields clients; `RunPauseControl.tsx` changes only worker scheduling. First read `src/app/toolAssignments.ts` and its small unit tests: tool IDs name renderers, keys name placements, `nextGalleryTool` chooses an unrepresented suitable default, and featured replacement differs from whole-assignment exchange. Then read `ToolDeck.tsx`, which renders one full-width feature above up to six gallery cards. A renderer may remount when exchanged between containers, so `FieldWorkspace.tsx` keys display range, comparison site and Fourier momentum by assignment; `OscillatorView.tsx` similarly keys path range and effective-gap lag. Both receive existing snapshots, not a sampling callback. `OscillatorTheory.tsx` runs optional transfer quadrature only for an open body and caches by validated parameters. For Stage C, read `LatticeSystems.tsx` for worker-owned state and segment commands, then `CanvasLattice.tsx` for read-only drawing/selection, `LatticeToolDeck.tsx` for tool IDs and shared nominal-sweep window, and `src/plotting/LatticePlots.tsx` for the unchanged scientific projections. Spatial displacement is keyed by assignment, while the selected canvas site is workspace state. `src/app/styles.css` scopes the singleton-card and phone detail/overview rules. Read `tests/browser/modelPageStageB.spec.ts` and `modelPageStageC.spec.ts` for layout, exchanges and display-only regression; `workspaces.spec.ts` checks independent sessions and seeded replay. For the extracted Ising local view, read `src/app/neighborhoodCells.ts` first: it maps displayed offsets onto row-major physical sites and distinguishes open-boundary absence from periodic images. `LatticeNeighborhood.tsx` renders those cells, while `LatticeSiteControls.tsx` shares the workspace-owned selection with `CanvasLattice.tsx`; `src/app/neighborhoodCells.test.ts` and `tests/browser/isingNeighborhood.spec.ts` cover the mapping and display-only behavior. For Stage D1, read `SmallSystemsApp.tsx` for small-run/session and selection ownership, `SmallToolDeck.tsx` for model-specific tool applicability and keyed histogram/viewport choices, `GraphWorkspace.tsx` for separated graph drawing, local readout and sidebar editor, and `Inspector.tsx` for the reused seven plots. `tests/browser/modelPageStageD1.spec.ts` compares display-changed and untouched worker captures. For Stage D2, follow `SmallSystemsApp.tsx` to `ScalarParameterEditor` in `ScalarWorkspace.tsx`: the editor alone owns draft coefficients, while the worker snapshot supplies applied state. `ScalarGraphVisualization` and `ScalarGraphInspection` read that snapshot and workspace-owned site/bond selection. Then read `ScalarToolDeck.tsx` for assignment-local observable, histogram, viewport and trajectory-window choices; `ScalarInspector.tsx` and `ScalarTrajectoryPlot.tsx` remain the scientific renderers. `tests/browser/modelPageStageD2.spec.ts` verifies placement changes against saved scientific captures. |

Run `npm test` for the unit tests beside the numerical modules. Run `npm run build` and then `npm run test:browser` for production-browser tests; `npm run check` also runs formatting and typecheck. For independent references, start with the Gaussian analytic moments in `gaussian.test.ts`, the hand-enumerated tiny Ising cases in `ising.test.ts`, the 2×2 physical reference comparisons in `latticeExact.test.ts`, and the separate `LatticeRun` point replay in `sweep.test.ts`. The tests should make the expected result intelligible without trusting the production function under test.
