## Delivered slice and architecture

Lattice QM's quartic/double-well model now offers its unchanged random-site Metropolis sampler and a new identity-mass HMC sampler for the same periodic action. A pure [`quarticPathGradient`](../src/models/quarticOscillator.ts) contains both closing-bond derivatives and the complete `r x+λx³−h` force. The React-independent [`quarticHmc.ts`](../src/algorithms/quarticHmc.ts) separates auxiliary Hamiltonian evaluation, deterministic kick-drift-kick integration and a complete-ΔH Metropolis transition. Each trajectory refreshes N Box–Muller Gaussian momenta and consumes exactly `2N+1` seeded uniforms including its decision draw. Nonfinite integration rejects and preserves the old path; finite positive ΔH uses the ordinary Metropolis probability, even if it is large.

[`FieldRun`](../src/engine/fieldRun.ts) remains the one worker-owned authority for path, RNG, action, counters, full-segment site/average/action-density moments and pair products. Its narrow discriminated quartic settings keep local warm-up/stride in nominal sweeps and HMC warm-up/stride in complete trajectories. One HMC Step is one full trajectory. Compatible physical, sampler or tuning changes preserve path/RNG and open isolated measurement segments; N/model changes and Reset restart a seeded session. A global transition index remains monotone for protocol compatibility, though its increments have sampler-dependent work units. At most eight segments and 256 recent paths per segment remain stored. HMC adds per-segment full-attempt acceptance/divergence and finite energy-defect mean/RMS/max, actual gradient/step counts, and at most 256 recent ΔH records; the latest trace retains at most L=32 *completed-step* defects, not full intermediate paths or momenta. Run batches at most 16 HMC trajectories, direct advances at most 32, while every existing sampler keeps its former 128-update Run batch.

The quartic page exposes explicit ε, L, `Lε`, warm-up and stride controls, a selectable HMC diagnostic, and a sampler-aware latest-transition inspection. The standard full-width path and gallery tools remain. A compact per-segment diagnostic layout is readable on narrow phones. Draft and presentation changes do not sample. The M4c1 transfer worker remains independent and lazy. Harmonic QM, spatial Gaussian fields, model switching, the archive schema and the `/lattice/` deployment path were not changed numerically.

For source readability, the force and HMC transition are short pure numerical modules with their equations beside the code. The deterministic integrator exposes real intermediate energy defects without storing full MD paths, and worker/client changes keep numerical ownership explicit. Hand-checkable four-site force, injected-draw and seeded-replay tests explain the conventions independently of React. The [source guide](SOURCE_GUIDE.md) adds a student reading order; no broad sampler framework or new numerical dependency was introduced.

## Scientific validation

[`quarticHmc.test.ts`](../src/algorithms/quarticHmc.test.ts) compares the full analytic force with independent centered full-action differences at N=4,6,8 and several β/N values, including Gaussian, quartic, negative-r, tilt and periodic endpoints. At λ=0 it also checks the independent periodic Gaussian precision matrix. For interacting and tilted nonstationary states, three ε/L pairs return to their original phase points within the test's `10⁻¹¹` decimal-scale gate; an independently finite-differenced 8×8 Jacobian has `|det J|` within the test's `10⁻⁷` decimal-scale gate of one. Kick and drift are triangular determinant-one shears, so the numerical Jacobian illustrates rather than establishes volume preservation. At fixed auxiliary duration 0.4, halving ε and doubling L in a smooth four-site fixture reduces final `|ΔH|` by factors between 3.5 and 4.5. Separate injected-draw tests check downhill and uphill proposals, complete `ΔH` rather than `ΔS`, rejection and divergence, fresh momentum, and the `2N+1` uniform budget.

The equilibrium gate runs **four independent fixed seeds** (`1203, 9041, 19383, 47017`) for each N=8, β=4 model, with 300 warm-up trajectories followed by 550 retained paths per chain at stride 4, ε=0.08 and L=14. For the displaced Gaussian (`r=1, λ=0, h=0.4`), the sampled path mean is **0.38876** versus exact **0.4**, and raw `C(0),C(a),C(2a)` are **0.65346, 0.47440, 0.35975** versus analytic finite-lattice **0.66393, 0.47693, 0.36915**. The average HMC acceptance fraction is **0.9959**. For the moderate quartic (`r=1, λ=1, h=0`), sampled `C(0),C(a)` are **0.34623, 0.17982** versus independently resolved finite-spacing transfer **0.34275, 0.17575**, with acceptance **0.9960**. These are deterministic multi-seed tolerance checks, not independent-sample error bars or proof of mixing. The symmetric double-well transfer gap near 0.3292113 remains a transfer-operator reference, never an HMC acceptance/mixing target.

Worker/client tests compare Step-by-Step with unequal batches and a seeded Reset, keep path/RNG across parameter/tuning changes, separate local/HMC/local segments, retain repeated rejected configurations as eligible measurements, preserve full pair products after recent-vector eviction, reject invalid settings and oversized direct HMC requests atomically, verify 16-versus-128 batch policy, and test Pause/Resume/Step plus a parameter change queued after a posted batch. Existing M4c1 quartic local and harmonic/Gaussian regression tests cover the previous numerical streams. The browser test reads real worker-derived controls and trace values; no browser-only HMC approximation was added.

## Presentation, resources and limits

Production browser tests cover desktop Chromium, 360px Chromium and mobile WebKit: sampler choice and HTML range validation, one whole-path Step, trajectory warm-up/stride, actual rejected proposal, Run/Pause/Step, seeded Reset replay, algorithm and physical segments, HMC diagnostic selection, display-only tool/range changes, a simultaneous lazy transfer analysis, harmonic model switch and no horizontal overflow. Screenshots: [desktop](screenshots/m4c2-desktop.png) and [360px phone](screenshots/m4c2-phone.png). The browser workload test times **Run click through at least 16 worker-completed trajectories visible in the DOM**, so it includes scheduling, worker execution, rendering and test polling; it is not a pure kernel benchmark or a low-end physical-phone measurement. In the complete six-worker browser run, local desktop Chromium recorded 113 ms at N=16 and 102 ms at N=64; 360px emulated Chromium recorded 129 ms and 79 ms, and mobile WebKit recorded 101 ms and 85 ms. Scheduling and polling noise explains why smaller N need not have shorter end-to-end latency. All were below the conservative 15-second responsiveness gate with transfer analysis open. No physical-phone performance claim is made.

`npm run check` passed formatting, TypeScript, **431 unit tests**, production build and **307 browser tests** across desktop Chromium, 360px Chromium and mobile WebKit. The **two pre-existing sweep-budget browser tests remain skipped**; no HMC test is skipped. An earlier repeated six-worker run exposed a pre-existing Stage D2 test race: it captured its displayed scalar state before the twelfth worker Step acknowledgment. That test now waits for the acknowledged update count; no scalar numerical code changed. The complete pipeline passed after this correction. Vite retains its existing large-main-chunk advisory. GitHub Actions independently passed validation and Pages deployment at the implementation commit.

A public-site Chromium smoke test of [Lattice Lab](https://gantemur.github.io/lattice/) at 1280px and 360px selected HMC, applied trajectory cadence, Stepped, opened the HMC diagnostic, Ran beyond 16 updates and Paused. Both views reached 113 actual worker transitions, loaded 13 local `/lattice/assets/` responses with no HTTP error, had no page errors and had no horizontal overflow. This verifies the deployed controls and static asset base path; it is not a physical-phone performance measurement.

The ε=0.002–0.25 and L=1–32 controls are teaching/resource bounds, not an automatic stability guarantee. A fine time lattice or stiff potential may need a smaller ε; the application never silently retunes it. The optional ΔH diagnostic measures auxiliary integration quality, not physical energy, quantum gap, equilibrium, independent uncertainty or cumulative Monte Carlo drift. Sign changes are cadence-dependent movement indicators, not a physical tunneling rate. Trajectories cost many force evaluations and cannot be compared to local proposals at equal update counts. No spatial φ⁴/HMC, nonidentity mass, adaptation, ESS, plateau fit or archive schema is added.
